# 出场单生命周期重构（挂单 ≠ 了结）

## Context（为什么做）

`SignalGridStrategy` 现在把"出场单挂出"当作"仓位已了结"：`check_close_position()` 返回 `exit_positions + remove_positions`，`record_positions()` 对传入项一律移除并归档（`active=0`）。后果：

- 出场限价单未成交时仓位已脱管；重启后 `load_positions`（只取 `active=1`）再也找不回 → 永久裸露敞口。
- 多仓位共用一张聚合出场单与同一个 `exit_id`，部分成交时每个仓位都用同一成交量扣减 → 归因错误、少挂超卖。

目标：建立"出场是有生命周期的"这一不变量，堵住脱管与超卖。已确认决策：**A 显式生命周期 + B 跟踪无条件执行 + C 每仓位一张出场单**；未成交时**保留原挂单**，强制出场可覆盖。

## 目标不变量

1. 仓位只有在**出场单确认成交且当前可平量 ≤ 0**时才归档。
2. **每仓位一张出场单**（独立 `exit_id`），成交可独立归因。
3. **跟踪无条件执行**：不挂在触发条件内部、不被开仓短路、暂停后仍执行。
4. 挂单未成交且价格回落 → **保留原挂单**，仓位保持 EXIT_PENDING。
5. 可平量守恒：持仓可平量随出场成交递减，任何路径都不得超卖。

## 状态（隐式编码，不新增枚举）

- **HOLDING**：`exit_id is None`
- **EXIT_PENDING**：`exit_id is not None`
- **ARCHIVED**：移出活跃集 + journal `active=0`

## 改动

### 1. `GridPosition`（`smart_trader/strategy/signal_grid_strategy.py`）
- `filled_quantity` 语义明确为**当前可平量**：入场成交后 = 入场成交量；出场部分成交后递减（决策：复用该字段，不改 DB schema）。
- `effective_filled_quantity` 的旧数据兜底条件收紧为 `status is CLOSED and filled_quantity == 0 and exit_id is None`，避免出场结算清零后被旧兜底"复活"成整仓。
- 新增 `has_pending_exit` 属性；新增结算方法（如 `apply_exit_fill(exited_qty)`）：`filled_quantity = max(0, filled_quantity - exited_qty)`。
- 更新 `.memory/02-domain-model.md` 中 `filled_quantity` 的说明。

### 2. 新增 `_track_pending_exits() -> tuple[list[GridPosition], bool]`
每根完成 K 线**无条件**执行；遍历所有 `has_pending_exit` 的仓位，`query(position.exit_id)`：

- **CLOSED**：`已成交 >= 可平量` → 归档；否则递减可平量并清 exit。
- **OPEN**：保留挂单（不撤、不重挂），保持 EXIT_PENDING。
- **CANCELED / REJECTED / EXPIRED**：走 `_cancel_and_refresh(exit_id)` 确认终态并取最终 `filled_qty` → 递减可平量、清 exit；可平量 ≤ 0 则归档。
- **query 返回 None**：**不直接清 exit**（None 可能只是新单索引延迟）；改走 `_cancel_and_refresh` 复核——cancel 返回 None 才认定订单不存在 → 退回 HOLDING；cancel 返回订单则按其结算。
- **query 抛 `SmartTraderError`**：保留 `exit_id`，等下一根重试（绝不重复下单）。

返回 `(archived, changed)`；`changed=True` 用于触发落盘。

### 3. 改造 `check_close_position() -> list[GridPosition]`
- 只对**无 pending exit** 的仓位做触发判定，且**每仓位各挂一张**出场单（数量 = 该仓位当前可平量，价格 = 当前收盘价）。
- 有 pending exit 的仓位：普通止盈/退出信号 → **跳过**（保留原挂单）；命中**强制出场**（`stop_loss_triggered` / `stop_loss_order_all` / 手动 `close_position`）→ 先撤休息挂单、结算已成交部分，再按剩余重挂。
- 返回值改为**只含可归档**的仓位（零成交入场单丢弃等）。

### 4. 调整 `_on_kline_finished()`
```
if latest_kline is None: return
refresh = False
if self.is_running:                      # 跟踪止损更新
    ...
archived, changed = self._track_pending_exits()   # 无条件, 暂停后仍跟踪
refresh = refresh or changed
if self.is_running:
    if not self.check_open_position():
        closed = self.check_close_position(); archived += closed; refresh or= bool(closed)
    else:
        refresh = True
self.position_manager.record_positions(archived, refresh)
```
关键：`is_running=False`（止损暂停）后**仍执行跟踪**，修复"暂停即停止跟踪、重挂的止损单再次脱管"这一缝隙。

### 5. `_on_kline()`（实时限价止盈路径）
已满足"每仓位一张单 + 确认成交才归档"，触发逻辑不动；归档判据与新方案对齐（改用可平量口径）。

### 6. 落盘
- 归档：`record_positions(archived)` → `sync_positions` 置 `active=0`（已有）。
- 挂单：`confirm_exit`（`storage/order_journal.py` L204-225）已同事务回写 `exit_id`。
- 清 exit / 递减可平量：由 `changed=True` 触发 `record_positions(refresh=True)` 的 upsert，保证重启幂等。

## TDD 计划（红 → 绿 → 重构）

新增测试（先写、先确认失败）：
1. **挂单不归档**：TP 触发挂出 OPEN 出场单 → 仓位仍在活跃集、journal `active=1`。
2. **确认成交才归档**：下一根 query CLOSED → 归档 `active=0`。
3. **保留原挂单**：挂出后价格回落且无新触发 → 不撤单、仓位保持、后续成交仍能归档。
4. **每仓位独立出场单**：两仓位触发 → 两张单、两个 `exit_id`；一张部分成交不影响另一张。
5. **部分成交后强制止损**：只重挂剩余，可平量正确递减。
6. **exit 单 CANCELED/EXPIRED**：结算已成交、退回 HOLDING、可重挂；剩余 ≤ 0 归档。
7. **query=None**：不直接清 exit；cancel 确认不存在才退回 HOLDING（不重复下单）。
8. **query 抛异常**：保留 `exit_id`、不重复下单。
9. **幂等**：同一根内重复跟踪不重复下单 / 不重复扣量。
10. **暂停后仍跟踪**：`is_running=False` 时 pending exit 仍被跟踪并归档。
11. **重启恢复**：pending exit 的仓位随 journal 加载后继续跟踪。
